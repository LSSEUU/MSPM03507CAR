# M5 临时数字灰度模块适配记录

日期：2026-07-24

## 原因与证据

原感为模拟量八路灰度模块在全白、全黑和贴近白纸条件下，CH7/CH8 始终约为 77–82 ADC；全白到全黑的逐通道变化量约为 `[2345,2324,2030,2031,2634,2631,0,0]`。地址真值表、GPIO 位操作、引脚复用和原始快照路径审计未发现软件映射错误，最终由用户确认原模块损坏并临时更换。

用户提供的临时模块资料位于 `docs/临时更换八路灰度模块/`。厂家手册和 MSPM0G3507 示例共同确认：

- 仍使用 CD4051、AD0/AD1/AD2 和单一 OUT，引脚真值表不变；
- OUT 是数字高低电平，不是可用于灰度幅值标定的模拟量；
- 厂家 MSPM0 示例在地址切换后等待 50 µs，巡线示例使用 100 µs 或更长；
- 模块指示灯点亮时示例读取为 1；固件因此默认高电平有效，并保留运行前切换有效电平的命令；
- 厂家推荐探头离地约 18 mm，EN 有 10 kΩ 下拉并默认使能。

用户已通电确认临时模块无损坏，OUT 不超过 3.3 V。该结论是用户电气检查，不等同于新固件上板验证。

## 实现范围

- PA23/PA24/PA26 继续作为 AD0/AD1/AD2；PA23 仍因天猛星 C44 耦合采用释放输出加内部上拉，不恢复普通推挽高电平。
- PA25 从 ADC0 A0_2 改为无上下拉、带迟滞的数字 GPIO 输入；冻结板级配置不再初始化或供电 ADC0。
- 灰度驱动继续使用偶数后奇数的非阻塞扫描顺序，每次地址稳定等待 1600 个 32 MHz 周期（50 µs），快照输出八路 0/1 和 `high_mask`。
- M5 控制层把八路数字有效状态直接转换为质心位置和置信度；默认 `ACTIVE_HIGH`，命令 `2` 可在 IDLE 切换为 `ACTIVE_LOW`。
- 原 5 s 数字通道覆盖确认已完成一次性八路物理验证；按用户要求，当前固件取消每次上电的该流程，固定使用 0/1 数字量程。当前线无效时仍不允许解锁。
- 巡线仍通过 App→Control→双轮速度闭环→Safety，丢线按最后方向低速搜索，持续 1500 ms 后锁存 `SAFETY_FAULT_LINE_LOST` 并停车。

## 自动化与目标构建

- 35 项 Python/C 整库主机回归全部通过；回归约束运行期 `r/v` 查询不得同步输出多行长报告，并冻结落地调参值。
- 数字模型覆盖固定八路 0/1、重复扫描过滤、高/低有效电平、左右位置、无线拒绝启动、跟踪、按最后方向搜索、恢复和丢线超时。
- Keil ARM Compiler 6.22 全量重建：0 error、0 warning。
- 诊断输出限时修复后的构建尺寸：`Code=22340, RO-data=4616, RW-data=4, ZI-data=19652`；AXF 280024 字节，HEX 75905 字节。

## 上板结果与问题定位

2026-07-24 用户手动下载并复位后，通过新 HC-04BLE 的 Windows Classic SPP `COM7`（115200 8N1）完成以下验证：

1. 左白右黑为 `[0,0,0,0,1,1,1,1] / high_mask=0xF0`，左黑右白为 `[1,1,1,1,0,0,0,0] / 0x0F`，确认 X1→X8 从左到右、黑色为高电平；扫描错误始终为 0。
2. 5 s 覆盖确认得到 `mask=0xFF`（500/501 个样本）；中间 X4/X5 为 `position=0.000`，X1/X2 与 X7/X8 分别为 `-0.857/+0.857`，置信度均为 1.000。
3. 架空居中 180/180 mm/s 连续运行 3.28 s，无故障或漏期；左线目标 17/343 mm/s、右线目标 343/17 mm/s，实际轮速方向与物理纠偏一致。
4. 从右侧有效线移到全白后进入 `SEARCH`，搜索目标 150/-60 mm/s；约 1500 ms 后锁存 `SAFETY_FAULT_LINE_LOST=0x100` 并使 PWM 归零。
5. M3 双轮 300 mm/s 隔离测试完整运行 5 s，误差 A/B=1.80%/1.72%，无复位、故障、漏期或 UART 丢包，排除了电机启动、供电和 HC-04 作为主要原因。

测试中两次在 M5 运行/故障事件附近连续请求 `r/v` 长报告，均在多行同步输出中触发 WWDT 复位 `0x20`；不追加查询、仅被动接收 M5 CSV 时连续运行正常。结合 M3 对照和历史同步报告问题，原因定位为诊断格式化突发占用主循环，使关键任务错过 31 ms 看门狗窗口。修复把 `v` 的 SAFETY/CONTEXT/SCHED 三行快照改为每 100 ms 一行，动作遥测期间延后输出，并把运行中的 `r` 限制为短提示。

修复版重新下载后完成两类复现回归：居中 M5 连续运行 4.15 s，运行中 `r` 返回短提示、`v` 延后到停车后分三行输出，最终 `faults=0`、`miss=0/0/0/0`；再次人工撤线触发 `0x100` 后，连续执行 `0/r/v/c/q`，安全/上下文/调度报告完整，覆盖 `mask=0xFF` 保留，扫描计数继续增长到 23637，未出现启动横幅、`0x20` 或计数清零。诊断复位问题因此验证关闭。

## 首轮落地与调参决定

重新覆盖并居中后，以 180 mm/s 落地运行 10.14 s，COM7 全程稳定且正常停车。100 个 CSV 样本中 TRACK=84、SEARCH=16，位置范围 `-1.0..+1.0`，修正范围 `-170..+170 mm/s`，左右目标均曾达到搜索反转值 -60 mm/s，`faults=0`、调度无漏期。用户确认车辆全程在赛道上，但弯道有转过头并出现轻微摆动，测试因 10 s 时间到结束，未跑完整圈。

结合位置/修正多次触及限幅和数字质心跳变会放大导数项，第一轮整定只做一次降激进修改：基速 `180→160 mm/s`、Kp `190→150 mm/s`、Kd `3→1 mm/s/(unit/s)`、最大修正 `170→150 mm/s`。失线搜索 45/105 mm/s 与 1500 ms 超时保持不变。该版本需要重新下载后比较弯道过冲、摆动和完整单圈能力。

调参版 Keil ARM Compiler 6.22 全量重建为 0 error、0 warning：`Code=22324, RO-data=4616, RW-data=4, ZI-data=19652`；AXF 279932 字节，HEX 75860 字节。

调参版下载后重新完成 `mask=0xFF` 覆盖确认，然后落地运行 22.4 s。共收到 224 个 CSV 样本，TRACK=207、SEARCH=17，位置覆盖 `-1..+1`、修正覆盖 `-150..+150 mm/s`，故障码始终为 `0x00000000`。用户观察表现基本没有问题；随后因外界原因人工断电，与遥测中断时刻一致。该次不归类为固件故障，但因中途终止不计完整单圈验收。

## 取消每次上电覆盖确认

临时模块 OUT 已是板上比较器产生的 0/1 数量，5 s 流程只能做通道覆盖检查，无法产生可用的模拟校准参数。在八路、极性和电平已上板确认后，用户要求取消该上电门槛。新实现直接按固定 0/1 计算位置与置信度；命令 `1` 只返回“已禁用”提示。启动仍要求连续两个扫描周期获得有效线，且仍需 `3`→`A` 二次确认；丢线搜索与 1500 ms 安全停车未改动。

改动后 35 项整库主机回归通过。Keil ARM Compiler 6.22 全量重建 0 error、0 warning：`Code=25156, RO-data=4884, RW-data=4, ZI-data=19892`；AXF 312332 字节，HEX 84561 字节。该版尚未下载。

## 剩余边界

1. 新版上电后不执行命令 `1`：黑线居中时可直接 `3`→`A`，全白无线时 `3` 必须拒绝；
2. 标准赛道完整单圈，确认实际曲率和安装高度下不会持续摆动、丢线或冲出边界；
3. 至少连续 3 圈，期间无人工干预、无故障、无出界；必要时仅基于 CSV 证据调整 M5 默认参数。

在这些项目完成前，M5 仍为“进行中”，不得宣称赛道多圈或最终硬件验收通过。
