# 灰度传感器自动标定操作手册

适用固件：`M6-runtime-20260728-r15` 及之后包含 `GRAYSCALE_CALIBRATION` 能力的版本

适用赛道：浅色背景、黑色轨迹线

标定方式：网页向导或红外遥控器

## 1. 功能说明

自动标定会分两阶段采集八路灰度传感器数据：

1. 全部探头放在白底上，采集 64 个有效且不重复的完整扫描。
2. 全部探头放在足够宽的黑线上，再采集 64 个有效且不重复的完整扫描。
3. 系统逐通道检查极性、跨度、噪声和 ADC 轨触碰。
4. 操作员确认后写入 Flash；写入并回读验证成功后，新标定才会生效。

取消、超时、断线、急停、质量检查失败或 Flash 写入失败都不会替换原有标定。上电时优先加载最后一次有效的 Flash 标定；没有有效的新格式记录时自动使用编译期标定。

> 标定不是运行中自适应功能。更换场地、赛道材料、传感器安装高度或环境光线明显变化后，应在发车前重新执行。

## 2. 标定前准备

准备一块与赛场背景相同或尽量接近的浅色平面，以及一段能同时覆盖全部 8 路探头的宽黑线。

开始前逐项确认：

- 车辆处于 `IDLE`，轮毂完全停止，电机没有输出。
- Safety 无故障，当前没有动作测试、循迹、WASD、红外驾驶或待应用参数。
- 小车放置稳定，采集期间不会被推动、抬起或晃动。
- 传感器安装高度和比赛时一致，镜头/探头表面清洁。
- 环境照明接近实际比赛状态，避免手、衣物或其他物体在探头上形成移动阴影。
- 灰度模块供电和接线可靠；模拟 `OUT` 接 PA25，任意通道电压均不得超过 3.3 V。
- 使用红外方式时，OLED 必须存在并能正常显示；没有 OLED 时请使用网页方式。

标定期间固件会拒绝循迹、动作测试、WASD 和红外驾驶等运动命令。急停始终有效。

## 3. 网页标定流程

### 3.1 启动控制面板

已经安装 Python 主机工具时，在项目根目录执行：

```powershell
m6-tune --port COMx dashboard
```

将 `COMx` 替换为车辆实际串口；省略 `--port COMx` 时工具会自动探测。默认打开 `http://127.0.0.1:8765/`。

如果尚未安装工具，可先执行：

```powershell
python -m pip install -e .\python
```

确认页面顶部显示“串口数据在线”，然后在“八路灰度”区域点击“自动标定灰度”。

### 3.2 第 1 步：采集白底

1. 点击“开始向导”。
2. 将全部 8 路探头放在同一块白底上；任何探头都不能压到黑线、缝隙或边缘。
3. 确认车辆和光源稳定后，点击“采集白底 64 帧”。
4. 等待进度达到 `64 / 64`。采集中不要移动小车或遮挡探头。

单阶段 5 秒内未收齐 64 帧会进入失败状态。修正原因后点击“重试白底”。

### 3.3 第 2 步：采集黑线

1. 将车辆平移到宽黑线上，使全部 8 路探头完整覆盖同一黑色区域。
2. 不要改变传感器安装高度，也不要用手按住或遮住传感器。
3. 点击“采集黑线 64 帧”。
4. 等待进度达到 `64 / 64`。

失败时修正放置、光线或接线，然后点击“重试黑线”。如果白底样本也可能不可靠，应取消并从白底重新开始。

### 3.4 第 3 步：检查结果

网页会显示 CH1～CH8 的白底值、黑线值、跨度、最大峰峰噪声和检查结果。每个通道必须同时满足：

- 没有采到 ADC 最小轨 `0` 或最大轨 `4095`。
- 白底平均值大于黑线平均值。
- `白底值 - 黑线值 ≥ 512`。
- 跨度不小于白底/黑线两阶段最大峰峰噪声的 8 倍。

任一路不通过都不能保存。网页会直接列出失败通道和文字原因；修正后重试对应阶段。

### 3.5 第 4 步：保存

确认八路全部显示“通过”，且候选数值合理后，点击“确认并写入 Flash”。这是唯一会修改持久化标定的步骤。

页面依次显示“正在写入并回读 Flash”和“标定已保存并应用”即表示成功。保存成功后：

- generation 增加。
- 活动来源显示 `PERSISTED`。
- 新的 1/3、2/3 滞回阈值立即生成。
- 旧循迹电平、位置滤波和有效线状态被清空；系统会等待新的灰度扫描重新锁线。

网页关闭、主机会话断开或串口掉线时，网页发起但尚未保存的候选标定会自动取消。

## 4. 红外遥控器标定流程

红外方式必须有 OLED。网页与遥控器只能有一个标定所有者；另一端可以查看状态，但不能接管当前流程。

| 操作 | 按键 | OLED 典型提示 |
|---|---|---|
| 开始标定 | `5` | `WHITE OK=START` |
| 开始采集白底 | `OK` | `WHITE CAPTURE` |
| 开始采集黑线 | `OK` | `BLACK CAPTURE` |
| 确认保存 | `OK` | `CHECK OK=SAVE`，随后 `FLASH SAVED` |
| 重试失败阶段 | `OK` | `FAILED OK=RETRY` |
| 从白底重新开始 | `5` | `WHITE OK=START` |
| 随时取消 | `0` | `CANCELLED` |

完整操作顺序：

1. 车辆静止且无故障时按 `5`。
2. 全部探头覆盖白底，看到 `WHITE OK=START` 后按 `OK`。
3. 等待 `N=64/64`，OLED 自动进入黑线等待状态。
4. 全部探头覆盖宽黑线，看到 `BLACK OK=START` 后按 `OK`。
5. 等待 `N=64/64`；全部通道合格时出现 `CHECK OK=SAVE`。
6. 检查 `MASK=0` 和 `MIN` 数值后，再按一次 `OK` 写入 Flash。
7. OLED 显示 `FLASH SAVED` 后完成。

OLED 字段含义：

- `N=x/64`：当前阶段已采集的有效完整扫描数。
- `MASK`：综合失败通道掩码；`0` 表示八路全部通过。bit0～bit7 分别对应 CH1～CH8。
- `MIN`：八路候选标定中的最小白黑跨度，应至少为 512。
- `G`：当前 Flash generation；保存成功后会增加。

等待操作超过 120 秒会自动取消。自动取消或保存完成后，遥控器会返回普通空闲状态。

## 5. 常见失败与处理

| 提示/原因 | 常见原因 | 处理方法 |
|---|---|---|
| 白底值不高于黑线值 | 白黑样本放反、探头没有全部覆盖目标区域、传感器极性或接线异常 | 核对采集顺序和覆盖范围；从白底重新开始 |
| 白黑跨度不足 512 | 黑线/背景对比度不足、安装过高、供电不稳、通道损坏 | 使用实际赛道材料，恢复比赛安装高度，检查供电和单通道输出 |
| 跨度不足噪声的 8 倍 | 小车或光源移动、阴影、灯光闪烁、电源噪声 | 固定车辆，移开手和遮挡物，稳定照明与供电后重试 |
| ADC 触轨 0/4095 | 模拟量超量程、OUT/地址线接错、供电或模块异常 | 立即检查电压与接线；PA25 输入不得超过 3.3 V |
| 扫描链路错误 | PA25、PB1、PA24、PA26 或灰度模块连接异常 | 检查 OUT、AD0、AD1、AD2、GND 和模块使能 |
| 5 秒采样超时 | 扫描未持续更新或采样链路不稳定 | 保持车辆静止后重试；重复超时则检查硬件和诊断输出 |
| 无法开始/状态错误 | 车辆不在 IDLE、仍有故障/动作/驾驶、轮速或电机非零、存在待应用参数 | 正常停止车辆，取消动作，处理故障并完成或撤销参数操作 |
| 当前由另一端操作 | 网页或遥控器已经拥有标定流程 | 由当前所有者完成或取消后，再从另一端开始 |
| generation 已过期 | 标定开始后参数记录 generation 被其他保存操作改变 | 刷新状态并从白底重新开始，不要直接重复旧确认 |
| Flash 保存失败 | 供电不稳或写入/回读校验失败 | 原标定仍保留；稳定供电后重试，重复失败时停止比赛使用并检修 |

发生 Safety 故障或急停时，标定会取消并保留旧值。先查明故障原因，再按既有安全流程清除故障，不要为了继续标定直接绕过 Safety。

## 6. 标定后验证

保存完成后必须执行：

1. 在网页确认活动来源为 `PERSISTED`，记录 generation 和八路白/黑值。
2. 分别把探头静置在白底、黑线和正常骑线位置，检查八路变化方向及循迹位置是否合理。
3. 断电再上电，确认活动来源仍为 `PERSISTED`，generation 与保存后一致。
4. 使用串口诊断命令 `1`，复核运行时白值、黑值、跨度和滞回阈值。
5. 清空安全测试区域，先低速完成静态锁线和短距离测试，再进行至少一圈完整循迹。

建议分别在测试场和比赛场照明下执行一次标定与验证。若比赛场光线或赛道材料变化，应以比赛场最后一次合格标定为准。

## 7. 赛前快速检查清单

- [ ] 车辆静止、`IDLE`、Safety 无故障。
- [ ] 传感器高度、轮胎和车身状态与比赛时一致。
- [ ] 白底和黑线样本能同时覆盖全部 8 路探头。
- [ ] 白底 64 帧采集完成。
- [ ] 黑线 64 帧采集完成。
- [ ] CH1～CH8 全部通过，`MASK=0`，最小跨度不少于 512。
- [ ] 已明确确认写入 Flash，页面/OLED 显示保存成功。
- [ ] 活动来源为 `PERSISTED`，generation 已记录。
- [ ] 断电重启后仍加载同一标定。
- [ ] 已完成低速静态复核和至少一圈循迹。

## 8. 工厂备用方式

`scripts/calibrate_grayscale.py` 仍保留为工厂编译期标定工具，适用于首次定型、重建默认固件值或 Flash 运行时标定不可用的情况。正常赛前适配优先使用本手册的网页或红外自动标定流程。
