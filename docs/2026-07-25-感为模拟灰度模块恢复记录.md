## 实现内容

- 冻结板级配置重新启用 ADC0：12 位、VDDA 参考、软件触发单次转换、4 MHz ADC 时钟和有界结果轮询。
- 灰度驱动每通道平均 8 次，继续按 `0,2,4,6,1,3,5,7` 扫描，AD0 由 PB1 推挽输出；PA21 与 PA23 保持高阻。
- `Config/grayscale_config.h` 保存编译期白/黑数组和验证锁。每路要求 `white > black` 且跨度至少 512 ADC。
- 条件器按手册计算：进入黑线阈值 `(2×black+white)/3`，退出黑线阈值 `(black+2×white)/3`；中间区域保持上次状态，输出黑线为 1。
- `q` 输出原始八路 ADC 和 ADC 状态，`1` 输出编译标定与阈值，`2` 不再切换极性，`3/A/0` 和既有安全路径不变。
- 新增 `scripts/calibrate_grayscale.py`：通过 pyserial 分别采集 64 组全白和黑线数据，检查 ADC 触轨、扫描错误、方向、最小跨度及 8 倍峰峰噪声裕量，再输出可固化的 C 常量。
- 新增 `scripts/flash.ps1`，每次调用只执行一次既有 Keil/SWD 下载并要求日志出现 `Verify OK`；重试次数由操作者按仓库规则控制。

## 首个解锁版的 WWDT 证据与修复

用户说明先前未启用 Keil Debug 配置；启用后手动下载成功。COM10 命令 `1` 首先返回：

```text
LINE CAL verified=1 valid=1 mask=0xFF min_span=512
LINE CAL white=[2419,2420,2886,2887,940,941,3006,3007]
LINE CAL black=[72,73,79,80,79,79,142,142]
LINE CAL span=[2347,2347,2807,2807,861,862,2864,2865]
```

第五行阈值报告输出中途出现新的启动横幅；随后安全快照为 `faults=0x00000020`，即 `SAFETY_FAULT_WATCHDOG_RESET`。ADC 仍为 `errors=0`，电机输出为 0。代码检查确认 `1` 命令当时在一次轮询中同步格式化五行，而已有状态、安全和红外长报告均通过 100 ms 服务逐行输出。基于该证据，将标定报告改为冻结快照后每 100 ms 仅格式化一行；主机静态回归同时要求命令使用队列和分时服务。

修复版手动下载后的 COM10 复核结果：

- `1` 完整返回五行，包括 `verified=1 valid=1 mask=0xFF`、白/黑数组、跨度和完整的进入/退出阈值；观察窗口内无启动横幅或复位。
- `q` 返回 `scans=3075 errors=0`。
- `v` 返回 `state=IDLE faults=0x00000000 pwm=0,0`，调度 `miss=0/0/0/0`。

据此关闭命令 `1` 导致 WWDT 复位的缺陷；尚未进行电机动作和赛道验收。

## 静态线位与第二次 WWDT 证据

未启动电机时取得：

- 全白：`active=0x00 valid=0`，命令 `3` 返回 `M5 arm rejected: acquire the line first.`，安全故障、PWM 和调度漏期均为 0。
- 左侧黑线：CH1/CH2 ADC 降至黑线区，`active=0x03 position=-0.857`。
- 右侧黑线：CH7/CH8 ADC 降至黑线区，`active=0xC0 position=+0.857`。
- 由此确认 CH1→CH8 对应车辆左→右；首次视觉居中落在 CH5/CH6，`active=0x30 position=+0.286`，精确 CH4/CH5 居中仍待调整。

后续校正中心位置时，一次 `q` 后串口出现残片；重新连接后的扫描计数从 48320 回到 1024，`v` 明确返回 `SAFETY state=FAULT faults=0x00000020`。该命令当时仍在主轮询中一次格式化八路 ADC、扫描计数、错误数和六项转换状态，故将 `q` 快照改为：

1. 第一个 100 ms 时隙格式化 CH1–CH4，不换行；
2. 第二个时隙格式化 CH5–CH8、扫描计数和错误数并结束原 `GRAY adc=[...]` 行，以保持标定脚本兼容；
3. 第三个时隙单独输出转换状态。

这是同一长报告问题的第二次修复。40 项主机回归通过；Keil 6.22 全量构建为 0 error、0 warning，`Code=26332, RO-data=5356, RW-data=4, ZI-data=20164`，AXF 331444 字节，HEX 89196 字节。修复版尚未上板；若仍出现同类复位，将按仓库限制停止继续尝试修复变体。

## 标定脚本的 `q` 三阶段生命周期修复

主机标定脚本原先在解析第二阶段 `GRAY adc=...` 行后立即返回，未消费固件清除 `gray_report_pending` 的第三阶段 `GRAY ADC ...` 终止行，连续采样可能过早发送下一条 `q` 并被固件丢弃。现改为先保留已解析样本，收到对应终止行后才返回。

新增双事务假串口回归，每次事务均包含命令确认、由两段输出组成但保持解析兼容的 ADC 行和最终终止行。聚焦测试在修复前以 `next q issued before the prior GRAY ADC terminator was consumed` 按预期失败，修复后通过；随后 `scripts/test.ps1` 完整主机回归为 `Ran 41 tests in 1.550s`、`OK`。本次未改动固件、未重新运行 Keil 构建、未下载或进行硬件验证，PB1 物理改线和新标定仍未完成，验证锁保持 0。
