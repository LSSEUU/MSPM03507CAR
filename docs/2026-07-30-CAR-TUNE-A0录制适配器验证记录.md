# 2026-07-30 CAR-TUNE A0 录制适配器验证记录

## 1. 范围与结论

本记录先实现监督式自动调参的 A0 数据闭环，再按首次落地验证脚本连接新底盘完成架空 T1。全过程不改参数 Schema；参数候选演练只 Apply、明确拒绝后回滚，不写入 Flash。

结论：**A0 与 T1 已通过，可进入 T2 前馈采样。** dashboard 原生 `m6-dashboard-session-v1` 已能直接进入确定性评分器，也能转换为稳定的合并 CSV/JSON。三次新底盘真实动作均与操作员观察、动作 spec、原始遥测、停止段和派生报告一致；候选拒绝/回滚与主机会话重连也已验证。本文三次 `100 mm/s` 记录构成新底盘 T1 证据，其中双轮记录可作为 T2 的 `100 mm/s` golden 点；旧底盘记录仍不得作为性能 baseline。

## 2. 实现内容

- 新增 dashboard 多流适配器，使用 `device_time_ms`、每流 `sample_id` 和 gap 标志合并 `core/wheel/line/health`，不按主机到达顺序硬拼。
- 自动从动作 spec 推导 `wheel/ground/line` 模式与请求速度；旧记录缺少 spec 时允许显式覆盖。
- reset、sample gap/order、action reject/fault/cancel、非正常完成、急停、Safety、断连、存储故障及 incomplete session 均进入硬失败。
- `m6-tune score` 可直接读取 dashboard session 目录；`m6-tune adapt-dashboard` 可导出与既有评分/回放工具兼容的 CSV/JSON，且不改写原始 session。
- dashboard 动作确认结果会把实际 Arm spec 写入录制 manifest，避免 5 秒预录窗口之外的 Arm 事件导致动作目标丢失。
- 修正 V2 LINE 合并字段的半字节顺序：`line_info=(active_count<<4)|cluster_count`，与固件和评分器合同一致。
- 固件当前不发布动作终态事件时，录制器可在已观察到非零 CORE 目标后，根据“目标归零且无故障”的边沿确定性推断正常完成并保留 2 秒后滚；真实动作事件仍优先。
- dashboard 观察遥测使用 `CORE/WHEEL/LINE/HEALTH = 40/40/100/1000 ms`，实测无 gap/drop，并为控制 RPC 和高优先级帧保留串口余量；固件内部 5 ms 轮速控制周期不变。
- 评分软指标只使用动作有效区间；未稳定时的 rise-time 回退到动作结束，不再计入后滚；轮速模式不再误计架空时无意义的航向和循迹软指标。

## 4. 安全边界

- 适配器和评分命令只读证据，不执行 Arm、Confirm、参数 Apply 或 Save。
- `host_auto_confirm=false` 保持不变；每次实车运动仍由操作员逐次明确授权。本次用户分别给出左轮、右轮和双轮的准确确认口令后，主机才执行对应 Arm→Confirm；一条授权只消费一次。
- 实车动作始终先验证 `IDLE`、`fault_bits=0`、目标/PWM 为零且无活动录制；运行中监视故障、反向反馈、非选中轮串动和双轮明显失配，满足异常条件立即急停。
- T1 通过不授权 T2 自动运动；后续每个 `100/160/220/300 mm/s` 动作仍需报告动作范围并取得单独确认。
- 当前流程只允许 Apply 候选。没有用户看到最终参数 diff 后的明确授权，不调用 Save。
