# 控制类电子设计竞赛通用小车平台设计

日期：2026-07-21

## 1. 背景与决策

本项目面向控制类电子设计竞赛。正式赛题将在比赛开始时发布，因此当前阶段不针对某一道题目优化，而是先构建一套稳定、可测量、可调参、可扩展的两轮差速小车平台。赛题发布后，新增应用层任务适配题目，底盘驱动、闭环控制和安全机制原则上保持稳定。

采用“保留硬件适配，重建应用层和控制层”的演进方案：

- 保留现有 Keil 工程、MSPM0G3507 引脚配置和已完成的硬件调试成果。
- 保留并逐项验证电机、编码器、UART、JY61P 和八路灰度驱动的有效实现。
- 重建主循环、任务调度、运动控制、安全保护、诊断和巡线应用。
- 不在现有 `Source/empty.c` 上继续堆叠比赛功能。
- 不从空工程重写已经完成的板级适配。

## 2. 固定硬件范围

第一阶段固定使用以下硬件，不引入摄像头或其他传感器：

- 立创·天猛星 MSPM0G3507-64P 主控板，32 MHz 裸机运行。
- MG310 双直流减速电机及双路 AB 相编码器。
- D153C/TB6612 双路电机驱动板。
- 感为八路灰度传感器。
- JY61P 陀螺仪，UART2、9600 baud。
- HC-04 串口透传模块。
- SSD1306 OLED。
- 板载或外接状态 LED。

## 3. 目标与非目标

### 3.1 目标

- 建立可重复构建、下载和回归测试的固件基线。
- 所有固定外设具有独立诊断入口、明确状态和测试记录。
- 建立稳定的双轮速度闭环、航向控制、定距和定角运动能力。
- 实现黑白线极性可配置的稳定巡线、丢线搜索和安全停车。
- 所有关键传感器数据具有有效标志和更新时间。
- 建立急停、传感器超时、堵转、任务超期和看门狗保护。
- 支持 UART/蓝牙遥测、在线调参、OLED 状态显示和参数保存。
- 赛题应用只能通过运动命令和传感器快照使用底盘，不直接控制 PWM。

### 3.2 非目标

- 当前阶段不实现视觉识别、SLAM、复杂路径规划或 RTOS。
- 当前阶段不针对未知赛题编写专用动作逻辑。
- 不为了抽象而引入动态内存、复杂框架或与比赛无关的通用组件。

## 4. 总体架构

系统采用裸机协作式调度。1 ms 定时中断只维护时基并触发任务，复杂控制在主循环任务中执行。系统按以下层次组织：

```text
应用层 App
  ├─ 系统模式选择
  ├─ 手动诊断
  ├─ 巡线任务
  └─ 未来赛题任务
          ↓ MotionCommand：期望线速度、角速度
运动控制层 Control
  ├─ 运动学分配
  ├─ 航向控制
  ├─ 巡线位置控制
  ├─ 左右轮速度 PI
  └─ 滤波、斜坡和限幅
          ↓ 左右电机 PWM 请求
安全层 Safety
  ├─ 急停
  ├─ 传感器超时
  ├─ 编码器异常与堵转
  ├─ 控制任务超期
  └─ 动作超时与看门狗
          ↓ 安全裁决后的 PWM
硬件驱动层 Hardware
  ├─ Motor / Encoder
  ├─ Gyro / Grayscale
  ├─ UART / Bluetooth
  └─ OLED / LED
```

### 4.1 周期任务

| 周期 | 任务 |
|---|---|
| 1 ms | 系统时基、任务释放、运行时间监测 |
| 5 ms | 编码器测速、双轮速度 PI、电机安全输出 |
| 10 ms | 陀螺仪和灰度数据处理 |
| 20 ms | 巡线、航向控制和动作状态机 |
| 100 ms | OLED、遥测、健康状态和低优先级诊断 |

UART 接收和编码器计数使用中断，但中断只接收数据、累加计数或设置标志，不执行格式化输出、浮点控制或动作状态机。

### 5.1 模块约束

- `Source/main.c` 只完成初始化、调度和空闲处理。
- `Hardware` 是唯一允许直接访问外设寄存器的业务目录。
- `Control` 只处理数值、状态和控制算法，不包含寄存器访问或串口打印。
- `App` 产生运动意图，不直接操作电机 PWM。
- `Safety` 对最终电机输出拥有否决权，其他模块不能绕过。
- OLED 和遥测读取状态快照，不改变控制器内部状态。
- 取消跨模块可写全局变量；中断数据通过私有 `volatile` 缓冲区和原子快照传递。
- `board.h` 只保留板级基础定义，不反向包含所有硬件模块。
- 轮径、轮距、编码器参数、任务周期和默认控制参数集中存放。

## 6. 数据模型与控制链路

关键数据使用明确的结构体传递：

- 传感器快照：数值、有效标志、最近更新时间、错误计数。
- `MotionCommand`：目标线速度、目标角速度、命令更新时间和运行模式。
- 轮速目标：左右轮目标速度及限速状态。
- 控制输出：左右 PWM 请求、饱和状态和控制器健康状态。
- 安全状态：故障位图、首次发生时间、最后发生时间和故障上下文。

每个 5 ms 控制周期的数据流为：

```text
编码器原子快照 → 脉冲差分 → 轮速换算 → 低通滤波
陀螺仪帧     → 校验与角度归一化 → 航向快照
灰度扫描      → 校准与消抖 → 线位置/置信度
应用命令      → 线速度/角速度 → 左右轮目标速度
左右轮目标    → 双轮速度 PI → PWM 请求
传感器健康状态 + PWM 请求 → Safety → Motor
```

## 7. 系统状态和错误处理

系统状态转换为：

```text
BOOT → SELF_TEST → IDLE → RUN
          ↓          ↓      ↓
                 FAULT → 清除故障 → IDLE
```

- 上电和复位后立即保持电机制动。
- `SELF_TEST` 不允许车辆进入正常运行速度；需要转动电机的测试必须由操作者明确启动。
- 陀螺仪超过配置时间没有有效帧时，禁止依赖航向的动作并停车。
- 目标速度不为零而编码器持续无脉冲时，判定堵转并停车。
- 编码器速度超过物理上限或发生不合理突变时，本周期数据作废并记录故障。
- 控制任务连续错过周期时停车并记录调度故障。
- 巡线丢线后按最后有效方向低速搜索；超过限定时间后停车并进入故障状态。
- 串口急停具有最高优先级，不依赖当前应用状态。
- 只有当全部关键周期任务按时完成时才允许喂看门狗。
- 每个故障记录类型、时间、关键传感器值、目标速度和当时 PWM。
- 故障清除只允许返回 `IDLE`，不得直接恢复先前运动。

## 8. 开发里程碑

### M0：工程基线

统一 SysConfig 与生成文件来源，修复工程和文档不一致，建立稳定的 Keil 全量构建、HEX 生成和版本记录。验收条件是干净工作区可重复构建且生成文件不会被意外覆盖。

### M1：外设诊断

建立串口诊断菜单，分别验证电机、编码器、陀螺仪、灰度、OLED、LED 和通信。上电自检报告每个外设的 `OK`、`DEGRADED` 或 `FAULT`，串口可查看原始数据与错误计数。

### M2：调度与安全

建立 1 ms 时基、周期调度、系统状态机、急停、传感器超时、动作超时和看门狗策略。关键故障触发后 100 ms 内停止电机，控制周期内不存在阻塞式等待。

### M3：电机闭环

完成编码器参数标定、速度换算、滤波、双轮速度 PI、输出限幅和加减速斜坡。初始目标为稳态速度误差小于 5%，无持续振荡，左右轮可独立测试与调参。

### M4：航向控制

完成陀螺仪有效性检测、校零、角度归一化、直行纠偏和非阻塞定角转向。连续多次执行正负 90°转向，初始目标误差不超过约 2°。

### M5：巡线控制

完成黑白线极性配置、通道校准、位置与置信度计算、巡线控制和丢线恢复。验收要求在标准测试赛道连续多圈运行，不丢线、不冲出赛道，丢线超时后能够安全停车。

### M6：人机交互与调参

完成 UART/蓝牙命令、非阻塞遥测、OLED 状态页和参数保存。不修改代码即可调整运行速度、PID、滤波和巡线参数，并能选择恢复默认参数。

### M7：平台验收

完成连续运行、低电压条件、堵转、传感器断开、通信中断和任务超期测试。平台连续运行至少 30 分钟，异常情况下不会失控，并形成可复查的测试记录。

## 9. 测试与验证

### 9.1 PC 单元测试

使用主机 C 编译器验证与硬件无关的 PID、滤波、运动学、角度环绕、灰度位置、巡线状态和系统状态机。每个控制模块必须先有失败用例，再实现使其通过。

### 9.2 外设台架测试

将小车架空，验证电机方向与制动、编码器方向与计数、JY61P 帧率和校验、八路灰度原始状态、OLED、LED 及串口通信。测试电机时必须提供随时可用的急停输入。

### 9.3 底盘集成测试

依次执行定速、加减速、直线、定距、定角和巡线测试。UART 输出机器可读 CSV，至少包含时间、模式、目标轮速、实际轮速、yaw、灰度位置、PWM 和故障位。

### 9.4 场地回归测试

每次控制算法或驱动发生重要变更后，重复固定项目：直行 2 m、左右转各 10 次、巡线多圈、急停、陀螺仪断开、编码器断开和人为堵转。实测轮径、减速比、每圈编码器脉冲和赛道条件后，将相对指标换成最终物理指标。

### 9.5 每个里程碑的完成条件

- 有可重复的测试步骤和明确通过标准。
- 有串口记录或测试输出。
- 有简短测试结果文档。
- 全量构建和相关自动测试通过。
- 代码、配置、接线说明和测试记录在同一版本提交中保持一致。

## 10. 迁移策略

- 先建立新的系统骨架和诊断入口，不立即删除旧的 `empty.c` 演示程序。
- 每迁移一个驱动，先运行原功能对照测试，再切换新接口。
- 新旧路径不同时控制电机；通过构建配置或单一入口明确选择。
- M3 速度闭环通过后，旧的固定 PWM 直行退出正常运行路径。
- M4 通过后，旧的阻塞式右转测试退出正常运行路径。
- M5 通过后，将巡线作为第一个完整应用验证新架构。
- 旧代码仅在等价功能通过回归测试后删除。

## 11. 赛题适配原则

赛题发布后，新任务应优先组合现有能力：定速、定距、定角、巡线、停车和故障处理。只有当赛题提出新的物理能力时才扩展底层接口。赛题应用不得绕过运动控制和安全层直接写 PWM，不得通过阻塞延时实现动作，也不得关闭关键故障保护以换取单次运行成绩。
