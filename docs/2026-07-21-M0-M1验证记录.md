## M1 串口诊断入口

上电后 UART0 使用 115200 baud、8N1。启动过程始终保持两路电机为制动状态，等待约 750 ms 收集 JY61P 数据，然后输出每项 `OK`、`DEGRADED` 或 `FAULT`、样本数、错误数和原因。灰度扫描因 PA23 硬件阻断仅由操作者输入 `q` 触发，不在启动阶段自动执行。

| 命令 | 作用 | 通过标准 |
|---|---|---|
| `s` | 输出全部自检状态 | 每项均有状态、样本数、错误数和原因 |
| `d` | 输出全部原始数据 | 包含编码器、JY61P、灰度和通信计数 |
| `e` | 编码器原始计数 | 手转两轮时相应 count/edge 持续变化 |
| `y` | JY61P 原始角度与帧统计 | `valid` 持续增加，checksum/frame 错误不持续增长 |
| `i` | JY61P 引脚跳变探针 | 临时统计 PA21/PA22 跳变，结束后恢复 UART2；仅用于接线诊断 |
| `q` | 八路灰度原始位图 | 遮挡/移过黑白边界时 `raw` 位图发生对应变化 |
| `o` | OLED 棋盘格测试 | I²C 在 0x3C/0x3D 应答，屏幕显示棋盘格，输入 `p` 确认 |
| `p` / `f` | 独立记录/清除 OLED 目视结论 | `p` 后 OLED 状态为 `OK`；`f` 后回到 `DEGRADED` |
| `l` | LED 能力说明 | 当前载板仅有电源灯，因此应报告 `DEGRADED` 和 0 个可控 LED |
| `c` | UART0 统计 | 每发送命令，RX 计数增加；输出使 TX 计数增加 |
| `m` | 双电机及编码器联动测试 | 架空车轮后输入大写 `A` 解锁；A/B 轮正反转且两路 edge 都增加 |
| `S` / 空格 | 电机急停 | 电机测试任一阶段立即制动并退出 |

电机测试安全要求：车轮必须架空，操作者必须能立即发送 `S` 或空格；未收到大写 `A` 前不会输出 PWM。测试按 A 正转、A 反转、B 正转、B 反转执行，每段 500 ms、PWM 250，每段之间制动。

## 本次 M1 上板记录

供电与安全条件：主板由电池供电、车架悬空；DAPLink 的供电线断开，仅共地。电机测试前后均通过串口 `S` 验证急停回显和制动路径。当前已更换为不接 RST 的新 DAPLink及独立 CH340 USB-UART，目标 3.3 V 正常。

下载链路曾在目标先上电时出现 `RDDI-DAP Error / cannot read DP register 0x00`。将 CMSIS-DAP 设置为 SWD 1 MHz、`Connect=under Reset`、`Reset=HW RESET` 并勾选 `Reset after Connect` 后，DAPLink 先上电、再给目标上电可稳定得到 `Verify OK` 和 `Application running ...`。该错误发生在读取调试端口阶段，不构成应用改写 SWD 的证据；源码检查和自动回归均确认 PA18/PA19/PA20 未配置。

| 项目 | 实测证据 | 结论 |
|---|---|---|
| UART0 / 通信 | 独立 CH340 COM5，115200 8N1；命令接收、状态输出和急停回显均正常 | `OK`；HC-04 透传未单独验证 |
| 上电自检 | 复位后输出全部外设状态、样本数、错误数和原因 | `OK` |
| 编码器 | 手转记录包括 countA=478、countB=-419、edgeA=534、edgeB=639、errors=0；电机测试增量 A=1157、B=1336 | `OK` |
| 电机与急停 | 大写 `A` 解锁后完成 A 正/反、B 正/反四段；测试前后 `S` 均返回 `EMERGENCY STOP` | 编码器联动 `OK`；正反方向目视结论待补录 |
| JY61P | 模块 TX 接 PA22、RX 接 PA21；有效角度帧持续增加，checksum=0、frame=0；指示灯闪烁经购买者确认是正常工作表现 | `OK` |
| SSD1306 OLED | I²C ACK 错误为 0；操作者确认 OLED 可见且棋盘格显示 | `OK` |

## 初始灰度代码审查

初始提交 `accb981` 的 `Hardware/grayscale.c` 按 `AD2/AD1/AD0=000..111` 依次选择八路，地址译码与照片上的 74HC4051 真值表一致，OUT 按低有效数字量读取。但该版本不能证明八路循迹可用：

1. 旧入口 `Source/empty.c` 只调用 `Grayscale_Init()`，仓库内没有任何运行路径调用 `Grayscale_Update()`；
2. 一旦补上扫描调用，通道 0 切到通道 1 时会推挽置高 PA23，触发已经复现的硬件异常；
3. 默认 `min_bits=3` 会把只有 1–2 个有效黑点的常见窄线状态清零；
4. 原始位图在过滤后才保存，无法从旧状态量区分“确实无线”和“被最小黑点规则过滤”。

结论：初始代码包含一个形式完整的八路数字扫描驱动，但没有接入主循环，也没有通过当前核心板的 PA23 电气条件，因此不能正常形成八路循迹输入。

原作者另行说明该功能“只是没有启用，启用后可以正常使用”。这与仓库中“驱动存在但主循环未调用”的设计意图一致，但与当前板上复现结果冲突。除非能够确认原作者测试使用相同核心板修订、相同 C33/C34 装配状态，并能提供八个不同地址对应的独立 OUT 读数，否则该说明不替代当前硬件验证结论。
