## M1 串口诊断入口

上电后 UART0 使用 115200 baud、8N1。启动过程始终保持两路电机为制动状态，等待约 750 ms 收集 JY61P 数据，然后输出每项 `OK`、`DEGRADED` 或 `FAULT`、样本数、错误数和原因。灰度扫描由操作者输入 `q` 触发，以便明确记录不同黑白表面下的光学响应。

| 命令 | 作用 | 通过标准 |
|---|---|---|
| `s` | 输出全部自检状态 | 每项均有状态、样本数、错误数和原因 |
| `d` | 输出全部原始数据 | 包含编码器、JY61P、灰度和通信计数 |
| `e` | 编码器原始计数 | 手转两轮时相应 count/edge 持续变化 |
| `y` | JY61P 原始角度与帧统计 | `valid` 持续增加，checksum/frame 错误不持续增长 |
| `i` | JY61P 引脚跳变探针 | 临时统计 PA21/PA22 跳变，结束后恢复 UART2；仅用于接线诊断 |
| `q` | 八路灰度原始位图 | 遮挡/移过黑白边界时 `raw` 位图发生对应变化 |
| `o` | OLED 棋盘格测试 | I²C 在 0x3C/0x3D 应答，屏幕显示棋盘格，输入 `p` 确认 |
| `p` / `f` | 独立记录/清除 OLED 目视结论 | `p` 后 OLED 状态为 `OK`；`f` 后回到 `DEGRADED` |
| `l` | LED 能力说明 | 当前载板仅有电源灯，因此应报告 `DEGRADED` 和 0 个可控 LED |
| `c` | UART0 统计 | 每发送命令，RX 计数增加；输出使 TX 计数增加 |
| `m` | 双电机及编码器联动测试 | 架空车轮后输入大写 `A` 解锁；A/B 轮正反转且两路 edge 都增加 |
| `S` / 空格 | 电机急停 | 电机测试任一阶段立即制动并退出 |

电机测试安全要求：车轮必须架空，操作者必须能立即发送 `S` 或空格；未收到大写 `A` 前不会输出 PWM。测试按 A 正转、A 反转、B 正转、B 反转执行，每段 500 ms、PWM 250，每段之间制动。

## 本次 M1 上板记录

供电与安全条件：主板由电池供电、车架悬空；DAPLink 的供电线断开，仅共地。电机测试前后均通过串口 `S` 验证急停回显和制动路径。当前已更换为不接 RST 的新 DAPLink及独立 CH340 USB-UART，目标 3.3 V 正常。

下载链路曾在目标先上电时出现 `RDDI-DAP Error / cannot read DP register 0x00`。将 CMSIS-DAP 设置为 SWD 1 MHz、`Connect=under Reset`、`Reset=HW RESET` 并勾选 `Reset after Connect` 后，DAPLink 先上电、再给目标上电可稳定得到 `Verify OK` 和 `Application running ...`。该错误发生在读取调试端口阶段，不构成应用改写 SWD 的证据；源码检查和自动回归均确认 PA18/PA19/PA20 未配置。

### 商家 ADC 例程对照测试（2026-07-22）

仓库外的商家 `ADC_Interrupt` 例程按当前接线最小适配为 PA23/PA24/PA26 地址选择、PA25/A0_2 采样，ARM Compiler 6.22 全量构建 0 error、0 warning，并曾下载得到 `Verify OK`。这进一步确认商家原始实现同样通过 ADC 读取 74HC4051 OUT，而不是直接读取数字电平。

本次没有形成灰度功能通过证据：UART0 生成配置标称 9600，但实收数据不可解析且没有取得八路 ADC 数值；随后 CMSIS-DAP 两次出现目标访问失败，最新日志为 `Cannot access Memory / Target DLL has been cancelled`。物理 RST 后，两次 COM5/115200 监听均为 0 字节。按“两次仍无法解决即停止”约束，已停止继续换波特率、复位和试烧。当前只能判定商家方案接口类型为 ADC，不能判定例程或灰度实物在本车上正常工作；恢复稳定下载与可观测启动输出后再继续。

## 初始灰度代码审查

初始提交 `accb981` 的 `Hardware/grayscale.c` 按 `AD2/AD1/AD0=000..111` 依次选择八路，地址译码与照片及厂家手册的 74HC4051 真值表一致，但把模拟 OUT 直接按低有效数字量读取。该版本不能证明八路循迹可用：

1. 旧入口 `Source/empty.c` 只调用 `Grayscale_Init()`，仓库内没有任何运行路径调用 `Grayscale_Update()`；
2. 旧冻结配置同时驱动 UART2_TX/PA21 和灰度 AD0/PA23，而天猛星-64P 的 C44=1 µF 跨接两脚；直接照旧启用存在强耦合；
3. 默认 `min_bits=3` 会把只有 1–2 个有效黑点的常见窄线状态清零；
4. 原始位图在过滤后才保存，无法从旧状态量区分“确实无线”和“被最小黑点规则过滤”。
5. 厂家《感为无MCU八路灰度传感器手册》明确要求 5–12 V 供电、OUT 悬浮模拟输入并由 ADC 采集；“无 MCU”并不等于数字输出。当前主板选用 3.3 V，PA25 虽支持 A0_2，但旧驱动从未初始化 ADC。

结论：初始代码包含一个形式完整但接口类型错误的八路扫描驱动；它没有接入主循环、没有处理天猛星-64P 的 PA21/C44/PA23 耦合，也没有按厂家要求使用 ADC，因此旧提交本身没有形成可运行的循迹输入。当前修正版只恢复了无错地址扫描。

原作者另行说明该功能“只是没有启用，启用后可以正常使用”。“驱动存在但主循环未调用”这一部分属实，但其数字读取实现与厂家手册及左白右黑实测冲突；该口述不能替代 ADC 接口和供电要求。

## 天猛星-64P 原理图纠正

当前开发板原理图为 `docs/立创·天猛星MSPM0G3507开发板原理图.pdf`（3 页，创建日期 2024-11-14，SHA-256 `7EE56A15DB1177F04A1B54E1AABED44899ABA7506809DBC0F4F0648C9B936B4C`）。第 1 页确认：

- C33=10 nF 属于 NRST 复位网络，不连接 PA23；
- C44=1 µF 连接在 PA21/VREF− 与 PA23/VREF+ 之间；
- R4 为默认 `NC`，只有使用参考电压时才以 0 Ω 将 PA21/VREF− 接 AGND；
- 当前应用不需要 JY61P RX，因此 UART2 改为仅接收，PA21 保持高阻，PA22 接收 JY61P TX；
- PA23 采用输入缓冲开启的开漏输出，高电平由内部上拉形成并回读确认。

修正后下载为 `Verify OK`；连续灰度扫描 `errors=0` 且不复位，同时 JY61P 保持有效帧增长和 0 校验/帧错误。
