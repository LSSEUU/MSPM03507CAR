# M2 调度与安全验证记录

验证日期：2026-07-22

## 1. 完成范围

本次实现对应总体 spec 的 M2“调度与安全”：

- 32 MHz 下的 1 ms SysTick 单调时基；ISR 只更新时间和释放任务。
- 5/10/20/100 ms 协作式周期调度、待运行位、完成计数和漏期计数。
- `BOOT → SELF_TEST → IDLE → RUN` 与任意运行态进入 `FAULT` 的系统状态机。
- 串口中断级急停、传感器超时、动作超时、调度漏期和 WWDT 复位故障位。
- 故障锁存首发/末发时间、请求/实际 PWM 和动作截止时间；清故障只返回 `IDLE`。
- 安全层是运行期唯一 `Motor_SetPWM()` 调用方；诊断电机测试也不能绕过。
- UART0 RX/TX 环形缓冲、异步灰度扫描、OLED 分页面刷新和非阻塞诊断动作状态机。
- WWDT0 约 31 ms；每 20 ms 仅在 5/10/20 ms 关键任务全部按期完成时喂狗。

当前 M2 不包含 M3 的轮速估计、堵转判断和速度 PI，也不包含 M4/M5 的航向与循迹控制。

## 3. 故障响应设计上界

| 故障 | 检测/裁决路径 | 软件设计上界 |
|---|---|---|
| UART `S` / 空格急停 | UART0 RX ISR → `Safety_EmergencyStop()` → `Motor_Stop()` | 不等待周期任务；ISR 路径 |
| 动作超时 | 5 ms 安全任务检查截止时间 | 截止后 5 ms 内 |
| 必需传感器超时 | 5 ms 安全任务检查时间戳 | 超时阈值后 5 ms 内 |
| 周期任务漏期 | 1 ms ISR 置漏期位，主循环锁存调度故障并制动 | 正常可调度时约 1 ms；若 CPU 卡死则由 WWDT 处理 |
| CPU/主循环卡死 | WWDT0，LFCLK 标称 32.768 kHz、2^10 周期 | 标称约 31 ms 后复位 |

软件结构给出的上界均小于 spec 的 100 ms 目标，但本次没有测量 MCU 引脚/PWM 的实物响应时间。

## 4. 待上板故障注入

下载本版 HEX 后需要在车轮架空、急停输入随时可用的条件下复核：

1. `v` 确认周期计数增长且 `miss=0`，系统在自检后进入 `IDLE`。
2. `m`、`A` 启动电机测试；每一相确认 `S`/空格立即制动并进入 `FAULT`。
3. 在测试动作中人为停止动作状态机或注入短截止时间，确认 `ACTION_TIMEOUT`。
4. 运行声明依赖 JY61P/灰度的测试动作，断开对应传感器并记录 PWM 归零时间。
5. 用受控测试固件停止喂狗，记录复位原因 `WWDT0` 和 PWM 归零时间。
6. `x` 清故障后确认只回到 `IDLE`，电机不会自动恢复先前 PWM。
