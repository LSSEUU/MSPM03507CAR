# PB11 红外遥控接入验证记录

日期：2026-07-24

## 本次实现

- 冻结板级配置修订到 `20260725`：PB11 使用 `IOMUX_PINCM28_PF_TIMG0_CCP1`，TIMG0 以 32 MHz BUSCLK / 8 = 4 MHz、16 位自由运行、CCP1 双边沿捕获 VS1838B 解调输出。
- NEC 状态机校验 8 位地址/反码和 8 位命令/反码，LSB 先行；完整帧与合法重复码进入容量 7 的定长队列，时序错误、校验错误和队列溢出仅计数。
- 重复码要求已有有效完整帧，且与上一个合法完整帧或重复码的间隔不超过 180 ms；每个合法重复码续期继承窗口，应用层只允许方向键重复码刷新人工驾驶心跳。
- 已实现人工四方向轮速目标、100/160/220 mm/s 三档速度、250 ms 心跳制动、500 ms Safety 后备期限，以及直行 2 s、±90°、巡线的 10 s 确认流程。
- UART `0` 可正常取消非故障动作；`t` 提供 30 s 只读键码采集；`s/d` 输出红外与遥控状态。
- 红外应用不直接写 PWM，也不提供清故障入口。

- 增加板级静态回归，锁定 PB11/TIMG0_CCP1、4 MHz、双边沿捕获，并确认 UART0/UART2、TIMA1 PWM 等原配置仍在。
- 首版生产门控固件、只读边沿观测版、GPIO DIN 根因修复版、实测键表启用版、连续重复码修复版和运行期状态分行修复版的 Keil ARM Compiler 6.22 全量 Rebuild 均为 0 error、0 warning；最终运行期状态分行修复版为 `Code=25828, RO-data=5060, RW-data=4, ZI-data=19980`，AXF 315912 字节，HEX 86946 字节，35 项主机回归通过。

## 阶段一硬件验证（通过）

实物接收器以 3.3 V 接入 PB11，用户已用接线检查和万用表确认电气连接；接收器指示灯随遥控发射闪烁。GPIO DIN 根因修复版下载后，UART `t` 模式成功输出 17 个完整 NEC 帧。所有帧地址均为 `0x00`，17 个命令互不重复，地址反码均为 `0xFF`，命令反码均正确：

`Config/remote_config.h` 已按上述实测表冻结并设置 `IR_REMOTE_KEYMAP_VERIFIED=1`。主机测试同时锁定每个键与命令的精确绑定；生产固件下载后允许红外动作，但 `t` 采集期间仍会禁止全部红外车辆动作。当前证据包括一轮完整 17 键采集和连续长按修复后的架空复测；其余车辆响应仍归入阶段二，不在此处宣称通过。

首次实物诊断已确认接收器指示灯响应、接线和万用表电平正常；进入 `t` 后约五次按键统计为 `full=0/repeat=0/checksum=0/timing=340/overflow=0/queued=0`。这证明 PB11/TIMG0 捕获中断已发生，但解码器系统性拒绝边沿。为区分 GPIO 电平读回与捕获 tick 比例问题，后续诊断构建的 `s/d` 增加 `IR EDGE count/high/low/ticks(min/max/last)/pin`；本次只增加观测量，不修改时序窗口和车辆动作。

边沿观测版实测为 `count=424/high=0/low=424/ticks=2080..36646/pin=0`：tick 覆盖 520 µs 到约 9.16 ms，符合 NEC 解调波形；但 GPIO DIN 在 PB11 复用 TIMG0_CCP1 时始终返回低，导致原 ISR 把全部捕获都当作下降沿。根因已经定位。修复版不再用 GPIO DIN 判定电平，而以 VS1838B 空闲高和双边沿交替维护相位，并在 20 ms 帧间超时重同步；修复后成功取得上述 17 个完整帧，证明接收与 NEC 解码链路可用。

## 阶段二车辆验证（仅剩 100 mm/s 落地人工驾驶）

- 首次架空长按方向键时，车辆只短暂动作并输出 `IR manual heartbeat expired; normal brake to IDLE.`。代码审查确认重复码的 180 ms 有效期错误地始终从最初完整帧计时，合法重复码没有续期；因此连续长按约数百毫秒后，后续重复码被拒绝并触发 250 ms 正常制动。修复版增加独立连续性时间基准：完整帧初始化，每个合法重复码续期，相邻间隔超过 180 ms 仍拒绝。该修复通过主机边界测试和 Keil 构建后已下载，用户确认长按持续运动、松开后心跳制动的行为符合预期；连续长按缺陷关闭。
- 长按运行中发送 `s` 后，串口输出曾在 `REMOTE enable...` 中途截断，随后重新出现启动横幅；复位后的 `faults=0x00000020` 明确记录 WWDT0 复位。修复版在收到 `s` 时只冻结红外/遥控快照，三条状态分别在后续三个 100 ms 周期输出。该版下载后，用户在 160 mm/s 前进长按期间重新发送 `s`，完整得到 `full=1/repeat=17/checksum=0/timing=0/overflow=0`、`REMOTE state=1 direction=1 heartbeat_stop=0`、`SAFETY state=RUN faults=0 pwm=106,106`、`CONTEXT target=160,160 speed=152,162` 和 `SCHED miss=0/0/0/0 pending=0x00`，且没有新启动横幅；运行期 `s` 复位缺陷关闭。
- 用户确认 160 mm/s 架空前进、后退、原地左转和原地右转均正常；前进目标、轮速符号和 PWM 有上述串口快照，其余三方向为操作者目视证据。
- M6 `r3` 固件上，从默认 160 mm/s 依次实物短按 `*/*/#/#/#`，串口精确返回 `100/100/160/220/220 mm/s`。结束快照为 `full=5`、`repeat=4`、校验/时序/溢出/地址/未知键/动作拒绝均为 0，REMOTE IDLE、速度 220 mm/s，Safety IDLE、PWM 0/0、调度漏期 0；三档切换和边界同键重复通过。
- 100 mm/s 人工驾驶架空四方向的目标依次为 `+100/+100`、`-100/-100`、`-100/+100`、`+100/-100 mm/s`；220 mm/s 的对应目标依次为 `+220/+220`、`-220/-220`、`-220/+220`、`+220/-220 mm/s`。八次松键后的第一个 20 ms 样本都已将请求/斜坡/PWM 归零；220 mm/s 组滤波轮速峰值最高 233 mm/s。两组的故障、持续饱和、调度漏期、UART/遥测丢包和遥测间隙都为 0；记录为 `pb11-100-four-directions-r3.*` 和 `pb11-220-four-directions-r3.*`。
- 220 mm/s 架空长按前进连续做两次：两个动作段的请求都为 `220/220 mm/s`、从第一个非零请求到第一个零请求均为 3.36 s，滤波速度峰值分别为 `232/233` 和 `232/232 mm/s`，第二段稳态误差 1.42%。两次松开都由心跳正常制动，下一个 20 ms 遥测样本中请求/斜坡/PWM 均为 0；无故障、漏期、UART/遥测丢包或持续饱和。原始记录为 `docs/m6-data/2026-07-25/pb11-220-forward-repeat-r3.*`。
- 220 mm/s 长按期间人为遮住接收器：最后有效方向时刻按 Safety 期限反算为 `E=1449129 ms`，第一个请求/斜坡/PWM 全零样本为 `Z=1449380 ms`，故停车延迟 `Z-E=251 ms`，满足不超过 300 ms 的硬门槛。整段无故障、漏期、丢包或 WWDT 复位；记录为 `pb11-220-heartbeat-cover-r3.*`。
- 100 mm/s 直行演示经 `1 → OK` 确认后以 `100/100 mm/s` 运行，自然结束记录为 `pb11-100-straight-natural-r3.*`；另一次从第一个非零请求到第一个零请求为 820 ms，按 `OK` 后该零请求样本的斜坡/PWM 也全部归零，记录为 `pb11-100-straight-ok-stop-r3.*`。这组正式证据取代了早期操作时机不清的尝试。
- `+90°/-90°` 分别经 `2/3 → OK` 确认，遥测精确给出 `-150/+150` 和 `+150/-150 mm/s`；分别运行 2.20 s/1.82 s 后按 `0`，第一个零请求样本的斜坡/PWM 均为 0。这两组是架空选择/确认/停止路径证据，不替代 M4 落地角度精度。
- 只按 `1` 不确认时，10 s 后同时输出 `M4 test arm timed out` 和 `IR demo confirmation timed out`，907 个样本全程无运动输出；记录为 `pb11-straight-confirm-timeout-r3.*`。
- 灰度快照 `valid=0` 时按 `4` 得到 `IR demo arm rejected by current safety/precondition state`；当时 `gray_mask=0x1F`、`line_info=0x51`，是被算法判为歧义的异常宽线，不是完全无线。605 个样本全程请求/斜坡/PWM 为 0，`action_reject` 由 0 增至 1。将黑线保持在传感器下并确认 `valid=1` 后，`4 → OK` 从第一个非零请求到第一个零请求为 3.90 s；运行期间 `gray_mask=0x18`、`line_info=0x21`（2 路、1 簇）、位置 0、目标 `160/160 mm/s`，按 `0` 后该零请求样本的斜坡/PWM 也全部归零。记录为 `pb11-line-invalid-reject-r3.*` 和 `pb11-line-valid-confirm-stop-r3.*`；这只证明当前 `line_valid` 门控，不宣称存在额外的“覆盖确认已通过”持久状态。
- 完成四方向后用 `*` 把档位降回 100 mm/s。最终快照为固件 `M6-runtime-20260725-r3`、REMOTE/Safety IDLE、请求 0/0、PWM 0/0、故障 0、调度漏期 0，UART/遥测丢包 0；`full=56`、`repeat=500`、`checksum=0`、`overflow=0`，最后解码键为 `*` (`0xE916FF00`)，预期的异常宽线拒绝使 `action_reject=1`。`timing=26` 是包含本轮主动遮挡与不完整手按帧的累计计数；它在后续四方向操作中由 22 增至 26，但八个方向动作都正确解码，没有错误动作、持续输出或安全计数异常。
- 架空安全路径已全部取证；PB11 阶段二现在只剩以 100 mm/s 在无障碍平整场地做短距离人工驾驶。该项通过前，仍不允许高速落地。
